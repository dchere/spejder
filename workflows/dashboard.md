# spejder.workflows.dashboard

**Purpose:**
Dashboard extraction module for GUI workflows. Owns missing-skill materialization helper and queued rebuild worker behavior. Record shaping lives in `dashboard_records.py` and is re-exported from `dashboard.py`.

**Submodules:**
- `dashboard_records.py` — `build_dashboard_record`, `build_viewed_today_dashboard_records`. Defined here; re-exported from `dashboard.py` (facade import path unchanged).
- `dashboard.py` — `coalesce_rebuild_reasons`, `populate_missing_dashboard_skills`, `DashboardRebuildQueue` (including `rebuild()`), plus the two builder re-exports.

**API:**
- `coalesce_rebuild_reasons(reasons: list[str]) -> str` — defined in `dashboard.py`. Pure helper; returns the last reason with a queued-count suffix when multiple are pending (e.g. `"third (+2 queued)"`). Returns `""` for an empty list.
- `build_dashboard_record(…, translate_title: bool = True)` — defined in `dashboard_records.py`, re-exported from `dashboard.py`. When `True` (default) calls `_build_title_fields` to translate/cache the title; pass `False` to read `title`/`title_english` directly from the row (used for applied-jobs where titles are already stored in English). Includes `on_interview`, `interview_stopped`, `company_feedback`, `applied_at`, and `hidden` on dashboard records. Job card `skills` string comes from `_format_skills(get_job_skills_filtered(...))` (whitelist → blocked → bad-cloud; may rewrite cache when names drop) with no per-job count cap.
- `build_viewed_today_dashboard_records(db_path, runtime_profile, title_translation_cache)` — defined in `dashboard_records.py`, re-exported from `dashboard.py`. Shared helper: `local_day_start_utc_iso` + `get_viewed_today_jobs` (includes soft-hidden) → `build_dashboard_record` with rebuild defaults (`default_viewed=1`, `default_applied=0`, `translate_title=False`). Used by rebuild / inbox report / enrichment report writers; preserves `updated_at DESC` (no unviewed/score re-sort).
- `populate_missing_dashboard_skills` — defined in `dashboard.py`. Batch materialize via `materialize_jobs_skills` for rebuild scope rows (inherits live mid-batch active-rescore scope re-check); optional `on_progress(checked, total, updated[, eta_s])`, `on_status_message`, `eta_store_path`, and `rematerialize` (GUI sync passes the process `SkillsRematerializeCoordinator`) forwarded to materialize
- `DashboardRebuildQueue` (`queue`, `start_worker`, `rebuild`, `is_idle`, `wait_until_idle`) — rebuild loads triage listings with `exclude_hidden=False` (soft-hidden compete for LIMIT; badge totals via `get_jobs_count_by_category` default `exclude_hidden=True`; `len_relevant_items` / `len_not_relevant_items` count non-soft-hidden among the sliced cards), applied-stage subsets (`get_applied_jobs`, `get_interview_jobs`, `get_stopped_interview_jobs` — including soft-hidden), and Edited today via `build_viewed_today_dashboard_records`; passes them to `_render_html_dashboard` as Relevant / Not relevant / Applied / Interview / Stopped / Edited today (no Hidden tab; soft-hidden stay in category/stage panels; main client filters with Show hidden on five tabs; Edited today always shows all matching rows including soft-hidden; no triage cap on applied-stage / Edited today). Skills tab rows come from `_build_skills_tab_items` (`position_pct`, `position_count`, `occurrences`, `added_at`, `has_skill`, `want_to_learn`, `not_for_me`). Skills tab layout (top→bottom): action row with Block/Delete selected (when rows exist) and right-aligned **Sync from CV** (`#btn-sync-from-cv` → `POST /api/skill/sync-from-cv`); skills table; bad-cloud status last (`_render_skills_cloud_status_html`: ngram count, weights, cap, threshold, remaining blocked list with Forgive). Skills tab columns include **Not for me** after **Want to learn**. Portrait panel (opened via toolbar icon `#btn-portrait`, not the mode tab row) embeds committed text from `default_portrait_path` via `user_portrait.load_portrait`. `_rebuild_active` is set in the worker immediately before `rebuild()` so `is_idle()` does not briefly return true between dequeuing and rebuild start. `wait_until_idle` blocks until no rebuild is active and the pending queue is empty (used by inbox sync to keep the **Sync inbox** button disabled until report regeneration finishes); returns `False` on timeout.
- Dashboard templates (`dashboard.html`, `company_dashboard.html`): both include `partials/dashboard_chrome.css` (shared body/controls/card/skill-tags/manual/applied/cover/feedback/empty rules; body top margin `12px`, sides/bottom `24px`); main also includes `partials/dashboard_skills.css` (skills table, sort indicators, bulk bar, `.skills-action` nowrap, icon buttons). Main dashboard puts `#sync-inbox-status` in a `.page-header` flex row with the title (`align-items: flex-end`, status right-aligned; empty status hidden); the toolbar stays alone in `.controls-wrap`. Regenerate report uses `#btn-regenerate.is-busy` to spin the toolbar SVG instead of writing "Regenerating…" into `#regenerate-status` (timeout/error text still use that span; empty status is `display: none` so the toolbar group gap stays even). Corners stay a separate `{% include "partials/dashboard_card_corners.css" %}` in both (not folded into chrome). Company has no skills/ops/portrait CSS or JS. Both include `partials/dashboard_card_stage.js` (`resolveAppliedStage`, `moveCardToAppliedStage`, `ensureCompanyFeedbackUI`, `removeCompanyFeedbackUI`, `removeAppliedOnlyUI`, `syncAppliedStageUI`, `removeCardFromAppliedStages`), `partials/dashboard_card_actions.js` (`cardCountsInTriageTotal`, dashboard versions of `setApplied` / `setHidden`, plus `setOnInterview`, `setInterviewStopped`, `saveCompanyFeedback`, `deleteJob`, and `cleanJobSkills`), and `partials/dashboard_card_applied_extras.js` (raw-text + cover-letter three: `appendAppliedRawText`, `setCoverLetterRequested`, `saveCoverLetter` — request/save only; no client morph after save). Rebuilt applied-stage cards (main and company) surface a saved cover letter via SSR `<details class="cover-letter-viewer">` / `<pre class="cover-letter-saved-text">` from `_build_job_cards` when `cover_letter` is non-empty. Main dashboard also includes `partials/dashboard_ops.js` (`apiUrl`, report mtime / `fetchReportStatus` / `reloadWithTab` / `sleep` / `waitForRebuildThenReload`, inbox sync poll via `initInboxSyncStatus` / `pollSyncStatus`, mid-sync auto-reload via `maybeMidSyncReload` when `reload_generation` advances past `sessionStorage` (`spejder-sync-reload-generation`) — if server gen is **below** the stored handled value (process restart), reset storage to `0` as a new epoch before comparing; write handled before `reloadWithTab(currentMode)` (fallback `location.reload`); skip navigation when `tabRefreshInProgress` but still mark handled so Applied/tab wait does not stack a second reload; after reload `initInboxSyncStatus` resumes poll while sync stays `running`; regenerate, `ensureEmptyState` / `bumpPanelTotal` / `refreshCounts`, `switchTab`), `partials/dashboard_portrait.js` (dirty-leave helpers, generate/save, `refreshPortraitFromServer`, `updatePortraitStatus`), `partials/dashboard_skills_flags.js` (`skillsTableSort` declaration, flag box helpers, exclusive uncheck, `setUserSkill` / `setLearnSkill` / `setUnwantedSkill`, `focusSkillRow`, `openSkillsForSkill`), `partials/dashboard_skills_bulk.js` (selection, bulk bar, confirm, `removeSkillRows`, single + batch block/delete, `syncSkillsFromCv`), and `partials/dashboard_skills_sort.js` (`initSkillsTableSort` / Jinja `SKILLS_EMPTY_ADDED_AT_SORT`). Include order in the main `<script>`: panel consts → `profile_panel.js` → ops → `setMode` (with `confirmLeaveCurrentPanel` beside it) → card partials (`stage` → `card_actions` → `applied_extras`) → portrait → skills flags → bulk → sort → `setRelevant` / `setViewed` → `window.*` / inits. `applied_extras` sits between `card_actions` and portrait. Company has no Skills/Profile/Portrait/ops includes (excludes all three skills JS partials); company include order is stage → actions → applied_extras; company `apiUrl` / `ensureEmptyState` / `refreshCounts` stay duplicated. Company `bumpPanelTotal` is a no-op (company buttons have no triage totals; shared `dashboard_card_actions.js` still calls it). `test_dashboard_templates.py` asserts the company `bumpPanelTotal` body is empty (no `dataset.total`). Checking **Applied** / **On interview** / **Stopped** on the main dashboard moves the card (`moveCardToAppliedStage`), sets `Saved: …` + `refreshCounts()` on the card, then `await waitForRebuildThenReload(...)` (Applied-true → fixed `'applied'`; Interview/Stopped-true → `resolveAppliedStage(card).mode`) so the page waits for rebuild and reloads onto the target tab — does **not** route through `switchTab` (same-mode early return / idle+same-mtime would skip the wait). Uncheck keeps the current tab: Applied-false still returns the card to Relevant / Not relevant (or **Edited today** when still viewed) with **no** `setMode` / helper; Interview/Stopped-false only moves the card (no focus change). Shared `dashboard_card_actions.js` calls the helper only when `typeof waitForRebuildThenReload === 'function'`; company (no ops) keeps Interview/Stopped-true instant `setMode` and Applied-true no-nav. `file://` / status-API failure in the helper degrades to `setMode(mode)` (card already moved). Overlapping waits: helper entry early-returns when `tabRefreshInProgress` is already true (avoids double busy / clearing the lock mid-poll). **Hidden** checkbox (main only): soft-hide only — flips `hidden` via `/api/hidden`, stays on the current category/stage panel, bumps Relevant/Not relevant `dataset.total` ±1 when toggling soft-hide on those panels (`setHidden` is the only soft-hide bump), then calls main-only `applyShowHiddenFilter` when present. Leave/move/delete triage bumps (`setApplied` apply-from-triage, `setRelevant`, `setViewed`, `deleteJob`, `cleanJobSkills` viewed_cleared) gate on `cardCountsInTriageTotal` (Hidden unchecked / was unchecked before a soft-hide clear) so already soft-hidden cards do not skew denominators. Does **not** switch tabs, strip applied UI, or clear pipeline checkboxes. Main dashboard only: `#show-hidden-wrap` under the tabs bar (visible on relevant|not relevant|applied|interview|stopped; sessionStorage `spejder-show-hidden` `'1'`/`'0'`, default off); soft-hidden cards get `.is-soft-filtered` (`display:none`) when Show hidden is off — do not `remove()` cards; `refreshCounts` Relevant/Not relevant numerators exclude soft-hidden by `.hidden-wrap input:checked` state (not `.is-soft-filtered`, so Show hidden ON stays consistent with `data-total`); Applied/Interview/Stopped count all `.card`; `ensureEmptyState` uses visible (non-`.is-soft-filtered`) cards. Filter runs on toggle, entering the five filtered tabs, soft `setHidden`, and after `?tab=` restore; `DOMContentLoaded` calls `refreshCounts` after `applyShowHiddenFilter`. Edited today has no Show hidden control and always shows soft-hidden. Company has no Hidden tab, no `.hidden-wrap`, and no Show hidden. On the main dashboard, not-relevant unchecks Hidden and removes `.is-soft-filtered`, leaves applied stages via `removeCardFromAppliedStages`, and moves to **Edited today** when viewed (auto-Viewed when unviewed). An unviewed **relevant** move onto Relevant calls `bumpPanelTotal` on the source (−1 only when that panel is Relevant or Not relevant and the card counted in the badge total) and on the target (+1, same gate) before prepend; soft-hidden cards move without touching totals. The viewed → Edited today branch still only decrements the source when the card counted. **Viewed** true prepends to **Edited today** (clears Hidden / `.is-soft-filtered`; R/NR −1 only when `cardCountsInTriageTotal` before that clear) without `setMode`; does not move cards already on applied-stage panels; Viewed false returns to Relevant / Not relevant by category (keeps Hidden checked when non-applied soft-hide is preserved; +1 only when the card counts in the triage total; then `applyShowHiddenFilter`). Company `setViewed(true)` moves to Edited today (not Relevant / Not relevant). Shared JS helper `resolveAppliedStage(card)` returns `{ panel, mode }` for applied-stage panel placement and tab navigation. `setRelevant` / `setViewed` / `setMode` stay per-template (`setMode` on the main dashboard also covers Skills/Profile/`switchTab`). Static regression tests in `spejder/tests/test_dashboard_templates.py` render Jinja for function-body assertions; they assert Applied/Interview/Stopped check-true use the wait+reload helper (gated by `typeof`, no `switchTab`, `Saved:` before await), that `waitForRebuildThenReload` has no idle+same-mtime / `setMode(mode, true)` shortcuts and early-returns when `tabRefreshInProgress`, uncheck does not navigate, company lacks the helper function (Interview/Stopped-true fall back to `setMode`), that `setHidden` / `setViewed` do not call `setMode`, that soft `setHidden` stays put (no panel-Hidden move / no `removeAppliedOnlyUI`) and posts `/api/hidden`, that Show hidden markup/session key is main-only, and that both templates omit the Hidden tab. Tab order: … Not relevant → Applied → Interview → Stopped → Skills → Edited today. Mode string `'edited today'` toggles `#panel-edited-today`; checkbox label uses `.hidden-wrap` to avoid colliding with the CSS utility class `.hidden` (`display: none`). Interactive cards (`_build_job_cards`) end the feedback row with a right-aligned `.feedback-actions` group (`margin-left: auto` in `dashboard_chrome.css`) holding a compact **Clean skills** button (`.clean-skills-btn`, `cleanJobSkills`) immediately before a compact **Delete** button (`deleteJob`). `cleanJobSkills(jobId, triggerEl, options?)` posts `POST /api/job/clean-skills` with no confirm (Delete still confirms); when `options.preserveViewed` is true the body includes `preserve_viewed: true`. Success clears `.skill-tags` on every `[data-job-id]` for that id (empty placeholder); the server queues rematerialize+rescore in the background (append to a running skills batch when active, else a dedicated worker — not a full inbox sync). If the response has `viewed_cleared`, it unchecks Viewed, calls `removeAppliedOnlyUI` so Interview and Stopped wraps, the cover-letter block, and `.applied-date` do not survive the move (including a card `setRelevant` already moved off Applied, Interview, or Stopped), and moves the card from whatever panel it is on, including Applied, Interview, and Stopped, to Relevant or Not relevant to match the Relevant checkbox, adjusting the triage total via `bumpPanelTotal` the same way. When `viewed_cleared` is false, the card stays put (manual Clean skills button uses the default path; not-relevant auto-clean passes `{ preserveViewed: true }` so triage stays viewed). Failure leaves skills in place and shows the error in `.feedback-status`. Unchecking Relevant still saves today's feedback and the automatic viewed mark; after that save succeeds, both `setRelevant` copies call `cleanJobSkills(jobId, inputEl, { preserveViewed: true })` automatically (no confirm). `deleteJob` confirms with `window.confirm` before `POST /api/job/delete`; cancel leaves the card. Success removes every `[data-job-id]` for that id (Edited today can show the same job as another tab), calls `bumpPanelTotal(-1)` when a removed card was on Relevant or Not relevant and counted in the badge total (`cardCountsInTriageTotal`), then `refreshCounts()`. Failure leaves the card and shows the error in `.feedback-status`. Static report cards from `_render_html_from_items` have no Clean skills or Delete button. `.clean-skills-btn` is styled in `partials/dashboard_chrome.css`.
- Main dashboard tab buttons (`dashboard.html` only) call `switchTab(mode)` instead of `setMode` directly. When `serve-gui` is running, `switchTab` clears `#tab-refresh-status`, queries `GET /api/report/status`; if the rebuild queue is idle and `report.html` mtime matches the page's embedded `spejder-report-mtime` meta tag, it switches instantly via `setMode`. If idle but mtime already differs (stale page), it reloads immediately with `?tab=` (no poll delay). Otherwise it calls shared `waitForRebuildThenReload(mode)` (same helper as Applied/Interview/Stopped check-true): early-returns if `tabRefreshInProgress` is already true, otherwise sets that flag for the whole wait (so other `switchTab` clicks and overlapping checkbox waits early-return), uses the regenerate button busy state (`setRegenerateBusy` refcount so regenerate timeout/error cannot clear busy while tab-wait still holds it, and vice versa; no new `POST /api/report/rebuild`), polls until rebuild is idle and mtime **differs** from `pageReportMtime` (no idle+same-mtime shortcut; or 60s timeout), then reloads with `?tab=`. Portrait and Profile toolbar buttons stay on `setMode` (unlocked during tab refresh; no stale reload). `openSkillsForSkill` still uses `setMode`. `file://` or API failure on `switchTab` instant paths falls back to `setMode(mode, true)`; inside `waitForRebuildThenReload` the same failures fall back to `setMode(mode)`.
- **Profile** panel (main dashboard only, not company): toolbar `#btn-profile` (gear icon) sits immediately left of **Sync inbox**. Markup/CSS/JS live in `templates/partials/profile_panel.{html,css,js}` included from `dashboard.html`. `#panel-profile` mirrors Portrait (Save, status, dirty leave / `beforeunload` prompts, refresh from `GET /api/profile` on enter). Save POSTs only dirty field keys; server merges into live runtime. Empty skill-pattern rows are not dirty; Save is disabled until a real change exists. Panel help notes that keyword/score changes need Sync / Regenerate report for existing jobs. Failed saves restore the Unsaved edits status when still dirty. `setMode('profile')` toggles the panel; company dashboard has no Profile button or panel. Manual pre-commit UI checks: `managers/profile_editor.md`.

**Constraints:**
- Use explicit imports only.
- Callers keep `from spejder.workflows.dashboard import …`; `dashboard_records.py` must not import `dashboard.py`.
- Keep mutable dashboard runtime state per `DashboardRebuildQueue` instance (`_dashboard_lock`, signal/queue primitives, title translation cache); do not use module-level mutable globals.
- Preserve existing dashboard rebuild behavior and logging semantics during extraction.

**Context:**
Extracted from `spejder/workflows/gui.py` so `gui.py` focuses on server orchestration/wiring, while dashboard-specific threading and report rebuild logic stays isolated in this module.
