# spejder.workflows.dashboard

**Purpose:**
Dashboard extraction module for GUI workflows. Owns dashboard record shaping, missing-skill materialization helper, and queued rebuild worker behavior.

**API:**
- `coalesce_rebuild_reasons(reasons: list[str]) -> str` — pure helper; returns the last reason with a queued-count suffix when multiple are pending (e.g. `"third (+2 queued)"`). Returns `""` for an empty list.
- `build_dashboard_record(…, translate_title: bool = True)` — when `True` (default) calls `_build_title_fields` to translate/cache the title; pass `False` to read `title`/`title_english` directly from the row (used for applied-jobs where titles are already stored in English). Includes `on_interview`, `interview_stopped`, `company_feedback`, `applied_at`, and `hidden` on dashboard records. Job card `skills` string comes from `_format_skills(cached_skills)` with no per-job count cap.
- `build_hidden_dashboard_records(db_path, runtime_profile, title_translation_cache)` — shared helper: `get_hidden_jobs` → `build_dashboard_record` with rebuild defaults (`default_category` from row, `default_viewed=0`, `default_applied=0`, `translate_title=False`). Used by `DashboardRebuildQueue.rebuild`, `write_inbox_dashboard_report`, and enrichment report writes.
- `populate_missing_dashboard_skills` — batch materialize via `materialize_jobs_skills` for rebuild scope rows
- `DashboardRebuildQueue` (`queue`, `start_worker`, `rebuild`, `is_idle`, `wait_until_idle`) — rebuild loads applied-stage subsets (`get_applied_jobs`, `get_interview_jobs`, `get_stopped_interview_jobs`) plus hidden via `build_hidden_dashboard_records` and passes them to `_render_html_dashboard` as Applied / Interview / Stopped / Hidden tabs (Hidden shows all rows; no triage cap). Skills tab rows come from `_build_skills_tab_items` (`position_pct`, `position_count`, `occurrences`, `added_at`). Portrait panel (opened via toolbar icon `#btn-portrait`, not the mode tab row) embeds committed text from `default_portrait_path` via `user_portrait.load_portrait`. `_rebuild_active` is set in the worker immediately before `rebuild()` so `is_idle()` does not briefly return true between dequeuing and rebuild start. `wait_until_idle` blocks until no rebuild is active and the pending queue is empty (used by inbox sync to keep the **Sync inbox** button disabled until report regeneration finishes); returns `False` on timeout.
- Dashboard templates (`dashboard.html`, `company_dashboard.html`): checking **Applied** removes the card from the current tab and updates counters but does **not** switch tabs; unchecking returns to Relevant or Not relevant. **On interview** / **Stopped** checkboxes switch to the Interview / Stopped tabs when enabled; unchecking returns to Applied. **Hidden** checkbox parks the card on the Hidden tab (`setMode('hidden')`) and strips applied-only UI via `removeAppliedOnlyUI` (cover letter / manual-description blocks, `.applied-date` + `has-applied-date`, and interview/stopped wraps) so the live card matches a rebuilt Hidden card; unhide returns to Relevant / Not relevant by the Relevant checkbox. `setRelevant` while Hidden is still checked keeps the card on Hidden (category only) — does not move a still-hidden card onto Relevant / Not relevant; not-relevant auto-Viewed unchecks Hidden. Apply/Viewed true unchecks Hidden in the UI; company `setViewed(true)` from `#panel-hidden` also moves the card to Relevant / Not relevant by category. Shared JS helper `resolveAppliedStage(card)` returns `{ panel, mode }` for applied-stage panel placement and tab navigation. Static regression tests in `spejder/tests/test_dashboard_templates.py` assert that `setApplied`'s applied-true branch does not call `setMode`, that `setHidden`'s hidden-true branch calls `setMode('hidden')` and `removeAppliedOnlyUI`, and that `setRelevant` guards moves with `!stillHidden` (both templates). Tab order: … Stopped → Hidden → Skills. Mode string `'hidden'` toggles `#panel-hidden` via the existing CSS class `.hidden` (`display: none`); checkbox label uses `.hidden-wrap` to avoid colliding with that utility class.
- Main dashboard tab buttons (`dashboard.html` only) call `switchTab(mode)` instead of `setMode` directly. When `serve-gui` is running, `switchTab` clears `#tab-refresh-status`, queries `GET /api/report/status`; if the rebuild queue is idle and `report.html` mtime matches the page's embedded `spejder-report-mtime` meta tag, it switches instantly via `setMode`. If idle but mtime already differs (stale page), it reloads immediately with `?tab=` (no poll delay). Otherwise it shows **Refreshing…**, polls until rebuild is idle and mtime changes, then reloads with `?tab=` so the target tab is restored after reload. Programmatic navigation (checkboxes, `openSkillsForSkill`) still uses `setMode`. Portrait toolbar button also uses `setMode` (no stale reload). `file://` or API failure falls back to instant `setMode`.

**Constraints:**
- Use explicit imports only.
- Keep mutable dashboard runtime state per `DashboardRebuildQueue` instance (`_dashboard_lock`, signal/queue primitives, title translation cache); do not use module-level mutable globals.
- Preserve existing dashboard rebuild behavior and logging semantics during extraction.

**Context:**
Extracted from `spejder/workflows/gui.py` so `gui.py` focuses on server orchestration/wiring, while dashboard-specific threading and report rebuild logic stays isolated in this module.
