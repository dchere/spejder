# spejder.workflows.dashboard

**Purpose:**
Dashboard extraction module for GUI workflows. Owns missing-skill materialization helper and queued rebuild worker behavior. Record shaping lives in `dashboard_records.py` and is re-exported from `dashboard.py`.

**Submodules:**
- `dashboard_records.py` — `build_dashboard_record`, `build_hidden_dashboard_records`, `build_viewed_today_dashboard_records`. Defined here; re-exported from `dashboard.py` (facade import path unchanged).
- `dashboard.py` — `coalesce_rebuild_reasons`, `populate_missing_dashboard_skills`, `DashboardRebuildQueue` (including `rebuild()`), plus the three builder re-exports.

**API:**
- `coalesce_rebuild_reasons(reasons: list[str]) -> str` — defined in `dashboard.py`. Pure helper; returns the last reason with a queued-count suffix when multiple are pending (e.g. `"third (+2 queued)"`). Returns `""` for an empty list.
- `build_dashboard_record(…, translate_title: bool = True)` — defined in `dashboard_records.py`, re-exported from `dashboard.py`. When `True` (default) calls `_build_title_fields` to translate/cache the title; pass `False` to read `title`/`title_english` directly from the row (used for applied-jobs where titles are already stored in English). Includes `on_interview`, `interview_stopped`, `company_feedback`, `applied_at`, and `hidden` on dashboard records. Job card `skills` string comes from `_format_skills(get_job_skills_filtered(...))` (whitelist → blocked → bad-cloud; may rewrite cache when names drop) with no per-job count cap.
- `build_hidden_dashboard_records(db_path, runtime_profile, title_translation_cache)` — defined in `dashboard_records.py`, re-exported from `dashboard.py`. Shared helper: `get_hidden_jobs` → `build_dashboard_record` with rebuild defaults (`default_category` from row, `default_viewed=0`, `default_applied=0`, `translate_title=False`). Used by `DashboardRebuildQueue.rebuild`, `write_inbox_dashboard_report`, and enrichment report writes.
- `build_viewed_today_dashboard_records(db_path, runtime_profile, title_translation_cache)` — defined in `dashboard_records.py`, re-exported from `dashboard.py`. Shared helper: `local_day_start_utc_iso` + `get_viewed_today_jobs` → `build_dashboard_record` with rebuild defaults (`default_viewed=1`, `default_applied=0`, `translate_title=False`). Used by the same three report writers; preserves `updated_at DESC` (no unviewed/score re-sort).
- `populate_missing_dashboard_skills` — defined in `dashboard.py`. Batch materialize via `materialize_jobs_skills` for rebuild scope rows; optional `on_progress(checked, total, updated[, eta_s])`, `on_status_message`, and `eta_store_path` forwarded to materialize
- `DashboardRebuildQueue` (`queue`, `start_worker`, `rebuild`, `is_idle`, `wait_until_idle`) — rebuild loads applied-stage subsets (`get_applied_jobs`, `get_interview_jobs`, `get_stopped_interview_jobs`) plus Hidden via `build_hidden_dashboard_records` and Edited today via `build_viewed_today_dashboard_records` and passes them to `_render_html_dashboard` as Applied / Interview / Stopped / Edited today / Hidden tabs (Hidden and Edited today show all matching rows; no triage cap). Skills tab rows come from `_build_skills_tab_items` (`position_pct`, `position_count`, `occurrences`, `added_at`, `has_skill`, `want_to_learn`, `not_for_me`). Skills tab layout (top→bottom): action row with Block/Delete selected (when rows exist) and right-aligned **Sync from CV** (`#btn-sync-from-cv` → `POST /api/skill/sync-from-cv`); skills table; bad-cloud status last (`_render_skills_cloud_status_html`: ngram count, weights, cap, threshold, remaining blocked list with Forgive). Skills tab columns include **Not for me** after **Want to learn**. Portrait panel (opened via toolbar icon `#btn-portrait`, not the mode tab row) embeds committed text from `default_portrait_path` via `user_portrait.load_portrait`. `_rebuild_active` is set in the worker immediately before `rebuild()` so `is_idle()` does not briefly return true between dequeuing and rebuild start. `wait_until_idle` blocks until no rebuild is active and the pending queue is empty (used by inbox sync to keep the **Sync inbox** button disabled until report regeneration finishes); returns `False` on timeout.
- Dashboard templates (`dashboard.html`, `company_dashboard.html`): both include `partials/dashboard_chrome.css` (shared body/controls/card/skill-tags/manual/applied/cover/feedback/empty rules; body top margin `12px`, sides/bottom `24px`); main also includes `partials/dashboard_skills.css` (skills table, sort indicators, bulk bar, `.skills-action` nowrap, icon buttons). Main dashboard puts `#sync-inbox-status` in a `.page-header` flex row with the title (`align-items: flex-end`, status right-aligned; empty status hidden); the toolbar stays alone in `.controls-wrap`. Regenerate report uses `#btn-regenerate.is-busy` to spin the toolbar SVG instead of writing "Regenerating…" into `#regenerate-status` (timeout/error text still use that span; empty status is `display: none` so the toolbar group gap stays even). Corners stay a separate `{% include "partials/dashboard_card_corners.css" %}` in both (not folded into chrome). Company has no skills/ops/portrait CSS or JS. Both include `partials/dashboard_card_stage.js` (`resolveAppliedStage`, `moveCardToAppliedStage`, `ensureCompanyFeedbackUI`, `removeCompanyFeedbackUI`, `removeAppliedOnlyUI`, `syncAppliedStageUI`, `removeCardFromAppliedStages`), `partials/dashboard_card_actions.js` (dashboard versions of `setApplied` / `setHidden`, plus `setOnInterview`, `setInterviewStopped`, `saveCompanyFeedback`, `deleteJob`, and `cleanJobSkills`), and `partials/dashboard_card_applied_extras.js` (raw-text + cover-letter three: `appendAppliedRawText`, `setCoverLetterRequested`, `saveCoverLetter` — request/save only; no client morph after save). Rebuilt applied-stage cards (main and company) surface a saved cover letter via SSR `<details class="cover-letter-viewer">` / `<pre class="cover-letter-saved-text">` from `_build_job_cards` when `cover_letter` is non-empty. Main dashboard also includes `partials/dashboard_ops.js` (`apiUrl`, report mtime / `fetchReportStatus` / `reloadWithTab` / `sleep`, inbox sync, regenerate, `ensureEmptyState` / `bumpPanelTotal` / `refreshCounts`, `switchTab`), `partials/dashboard_portrait.js` (dirty-leave helpers, generate/save, `refreshPortraitFromServer`, `updatePortraitStatus`), `partials/dashboard_skills_flags.js` (`skillsTableSort` declaration, flag box helpers, exclusive uncheck, `setUserSkill` / `setLearnSkill` / `setUnwantedSkill`, `focusSkillRow`, `openSkillsForSkill`), `partials/dashboard_skills_bulk.js` (selection, bulk bar, confirm, `removeSkillRows`, single + batch block/delete, `syncSkillsFromCv`), and `partials/dashboard_skills_sort.js` (`initSkillsTableSort` / Jinja `SKILLS_EMPTY_ADDED_AT_SORT`). Include order in the main `<script>`: panel consts → `profile_panel.js` → ops → `setMode` (with `confirmLeaveCurrentPanel` beside it) → card partials (`stage` → `card_actions` → `applied_extras`) → portrait → skills flags → bulk → sort → `setRelevant` / `setViewed` → `window.*` / inits. `applied_extras` sits between `card_actions` and portrait. Company has no Skills/Profile/Portrait/ops includes (excludes all three skills JS partials); company include order is stage → actions → applied_extras; company `apiUrl` / `ensureEmptyState` / `refreshCounts` stay duplicated. Company `bumpPanelTotal` is a no-op (company buttons have no triage totals; shared `dashboard_card_actions.js` still calls it). `test_dashboard_templates.py` asserts the company `bumpPanelTotal` body is empty (no `dataset.total`). Checking **Applied** removes the card from the current tab and updates counters but does **not** switch tabs; unchecking returns to Relevant or Not relevant (or **Edited today** when still viewed). **On interview** / **Stopped** checkboxes switch to the Interview / Stopped tabs when enabled; unchecking returns to Applied. **Hidden** checkbox parks the card on the Hidden panel and strips applied-only UI via `removeAppliedOnlyUI` (cover letter / manual-description blocks, `.applied-date` + `has-applied-date`, and interview/stopped wraps) so the live card matches a rebuilt Hidden card, but does **not** switch tabs (`setHidden` does not call `setMode`); unhide moves the card back to Relevant / Not relevant by the Relevant checkbox while staying on the current tab. `setRelevant` while Hidden is still checked keeps the card on Hidden (category only) — does not move a still-hidden card onto Relevant / Not relevant; not-relevant auto-Viewed unchecks Hidden and moves to **Edited today**. On the main dashboard, an unviewed move between Relevant and Not relevant calls `bumpPanelTotal` on the source (−1 only when that panel is Relevant or Not relevant) and on the target (+1) before prepend; the viewed → Edited today branch still only decrements the source. **Viewed** true prepends to **Edited today** (and unchecks Hidden) without `setMode`; does not move cards already on applied-stage panels; Viewed false returns to Relevant / Not relevant by category. Company `setViewed(true)` moves to Edited today (not Relevant / Not relevant). Shared JS helper `resolveAppliedStage(card)` returns `{ panel, mode }` for applied-stage panel placement and tab navigation. `setRelevant` / `setViewed` / `setMode` stay per-template (`setMode` on the main dashboard also covers Skills/Profile/`switchTab`). Static regression tests in `spejder/tests/test_dashboard_templates.py` render Jinja for function-body assertions; they assert that `setApplied`'s applied-true branch and `setHidden` / `setViewed` do not call `setMode`, that `setHidden` still calls `removeAppliedOnlyUI` and posts `/api/hidden`, and that `setRelevant` guards moves with `!stillHidden` (both templates). Tab order: … Not relevant → Applied → Interview → Stopped → Hidden → Skills → Edited today. Mode string `'edited today'` toggles `#panel-edited-today`; mode string `'hidden'` toggles `#panel-hidden` via the existing CSS class `.hidden` (`display: none`); checkbox label uses `.hidden-wrap` to avoid colliding with that utility class. Interactive cards (`_build_job_cards`) end the feedback row with a compact **Clean skills** button (`.clean-skills-btn`, `cleanJobSkills`) immediately before a compact **Delete** button (`deleteJob`). `cleanJobSkills` confirms ("Clear skills and re-extract them on the next sync?") before `POST /api/job/clean-skills`; cancel does nothing. Success clears `.skill-tags` on every `[data-job-id]` for that id (empty placeholder). If the response has `viewed_cleared`, it unchecks Viewed, calls `removeAppliedOnlyUI` so Interview and Stopped wraps, the cover-letter block, and `.applied-date` do not survive the move (including a card `setRelevant` already moved off Applied, Interview, or Stopped), and moves the card from whatever panel it is on, including Applied, Interview, and Stopped, to Relevant or Not relevant to match the Relevant checkbox, adjusting the triage total via `bumpPanelTotal` the same way. When `viewed_cleared` is false, the card stays put. Failure leaves skills in place and shows the error in `.feedback-status`. Unchecking Relevant still saves today's feedback and the automatic viewed mark; after that save succeeds, both `setRelevant` copies ask the same confirm. Yes calls `cleanJobSkills` with `skipConfirm` (the cleaner unviews the job again and moves the card to Not relevant). No leaves the not-relevant, viewed card where the save put it. `deleteJob` confirms with `window.confirm` before `POST /api/job/delete`; cancel leaves the card. Success removes every `[data-job-id]` for that id (Edited today can show the same job as another tab), calls `bumpPanelTotal(-1)` when a removed card was on Relevant or Not relevant, then `refreshCounts()`. Failure leaves the card and shows the error in `.feedback-status`. Static report cards from `_render_html_from_items` have no Clean skills or Delete button. `.clean-skills-btn` is styled in `partials/dashboard_chrome.css`.
- Main dashboard tab buttons (`dashboard.html` only) call `switchTab(mode)` instead of `setMode` directly. When `serve-gui` is running, `switchTab` clears `#tab-refresh-status`, queries `GET /api/report/status`; if the rebuild queue is idle and `report.html` mtime matches the page's embedded `spejder-report-mtime` meta tag, it switches instantly via `setMode`. If idle but mtime already differs (stale page), it reloads immediately with `?tab=` (no poll delay). Otherwise it shows **Refreshing…**, polls until rebuild is idle and mtime changes, then reloads with `?tab=` so the target tab is restored after reload. Programmatic navigation (interview/stopped checkboxes, Applied-false, `openSkillsForSkill`) still uses `setMode`. Portrait and Profile toolbar buttons also use `setMode` (no stale reload). `file://` or API failure falls back to instant `setMode`.
- **Profile** panel (main dashboard only, not company): toolbar `#btn-profile` (gear icon) sits immediately left of **Sync inbox**. Markup/CSS/JS live in `templates/partials/profile_panel.{html,css,js}` included from `dashboard.html`. `#panel-profile` mirrors Portrait (Save, status, dirty leave / `beforeunload` prompts, refresh from `GET /api/profile` on enter). Save POSTs only dirty field keys; server merges into live runtime. Empty skill-pattern rows are not dirty; Save is disabled until a real change exists. Panel help notes that keyword/score changes need Sync / Regenerate report for existing jobs. Failed saves restore the Unsaved edits status when still dirty. `setMode('profile')` toggles the panel; company dashboard has no Profile button or panel. Manual pre-commit UI checks: `managers/profile_editor.md`.

**Constraints:**
- Use explicit imports only.
- Callers keep `from spejder.workflows.dashboard import …`; `dashboard_records.py` must not import `dashboard.py`.
- Keep mutable dashboard runtime state per `DashboardRebuildQueue` instance (`_dashboard_lock`, signal/queue primitives, title translation cache); do not use module-level mutable globals.
- Preserve existing dashboard rebuild behavior and logging semantics during extraction.

**Context:**
Extracted from `spejder/workflows/gui.py` so `gui.py` focuses on server orchestration/wiring, while dashboard-specific threading and report rebuild logic stays isolated in this module.
