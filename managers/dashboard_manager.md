# spejder.managers.dashboard_manager

**Purpose:**
Generate HTML dashboards for the reporting modules.

**Context:**
Used to summarize and render job offers into presentable HTML files.

**Submodules:**
- `dashboard_templates.py` — shared Jinja2 environment; `load_dashboard_card_corners_css()` reads canonical rules from `templates/partials/dashboard_card_corners.css`; `dashboard.html` and `company_dashboard.html` include that partial via `{% include "partials/dashboard_card_corners.css" %}` (corners stay a separate include, not folded into chrome); both also include `partials/dashboard_chrome.css` (shared body/controls/card/skill-tags/manual/applied/cover/feedback/empty rules + shared `.controls-actions` right-aligned flex group); `dashboard.html` also includes `partials/dashboard_skills.css` (skills table, sort indicators, bulk bar, selected/added-today row highlights, `.skills-table-scroll` pane with sticky thead, `.skills-action` nowrap, icon buttons) and `partials/dashboard_companies.css` (companies table, sort indicators, bulk bar, selected/added-today row highlights, `.companies-table-scroll` pane with sticky thead, `.companies-action` nowrap, icon buttons); main `dashboard.html` wraps title/tabs/Show-hidden in `.dashboard-sticky-chrome` and Skills/Companies tables in `*-table-scroll` so bulk bars + column headers stay put while the list scrolls; both dashboards also include `partials/dashboard_card_stage.js`, `partials/dashboard_card_actions.js` (`setApplied`, `setHidden` soft-hide only — no `bumpPanelTotal` on soft-hide, `setOnInterview`, `setInterviewStopped`, `saveCompanyFeedback`, `deleteJob`, `cleanJobSkills(jobId, triggerEl, options?)` — optional `preserveViewed` → body `preserve_viewed`; Applied/Interview/Stopped check-true call `waitForRebuildThenReload` when defined — main ops wait+reload (sets `Saved:` + `refreshCounts` before await; helper early-returns if `tabRefreshInProgress`); company keeps Interview/Stopped-true instant `setMode` and Applied-true no-nav; uncheck never changes focus), and `partials/dashboard_card_applied_extras.js` (raw-text + cover-letter three); `dashboard.html` includes `partials/profile_panel.{html,css,js}`, `partials/dashboard_ops.js` (`waitForRebuildThenReload` shared with `switchTab`; overlapping wait early-return; inbox sync status poll + mid-sync `reload_generation` → one-shot `reloadWithTab` via sessionStorage (reset stored gen on backward jump / process restart), skipped while `tabRefreshInProgress`; `quitServer` for `#btn-quit`), `partials/dashboard_portrait.js`, `partials/dashboard_skills_flags.js`, `partials/dashboard_skills_bulk.js`, `partials/dashboard_skills_sort.js`, `partials/dashboard_companies_sort.js`, `partials/dashboard_companies.js`, and `partials/dashboard_companies_merge.js` (after companies.js; Merge modal open/sort/fetch) via Jinja; main also includes `partials/dashboard_companies_merge_modal.html` (hidden `#company-merge-modal` shell) and Merge modal rules in `dashboard_companies.css` (company does not include ops/portrait/skills/companies CSS or JS and excludes skills + companies JS/modal partials; company includes `partials/dashboard_company_page_actions.js` after its local `apiUrl`)
- `dashboard_cards.py` — job card HTML (`_build_job_cards` for main/company dashboards; `_render_html_from_items` for simple report cards without applied-date overlays); class constants `RELEVANCE_SCORE_CLASS`, `APPLIED_DATE_CLASS` (+ title attrs); `card_panel` arg controls Applied / Interview / Stopped controls and company feedback UI; `hidden_control=True` (default) adds a **Hidden** checkbox (`.hidden-wrap`) checked from `item["hidden"]`; company passes `hidden_control=False` (no hide UI); right-aligned `.feedback-actions` group (`margin-left: auto` in `dashboard_chrome.css`, same pattern as `.skills-bulk-bar-end` / `.controls-actions`) holding a compact **Clean skills** button (`.clean-skills-btn`, `onclick="cleanJobSkills({id}, this)"`; no confirm — server clears skills and queues rematerialize; button path omits `preserve_viewed` so non-pipeline jobs unview; not-relevant `setRelevant` auto-clean passes `{ preserveViewed: true }`) immediately before a compact **Delete** button (`.delete-job-btn`, `onclick="deleteJob({id}, this)"`; confirm, then remove every `[data-job-id]` for that id and `bumpPanelTotal(-1)` when a removed card was on Relevant or Not relevant (including soft-hidden); failure leaves the card and writes the error into `.feedback-status`; static `_render_html_from_items` cards have no Clean skills or Delete button); applied cards include optional cover-letter checkbox + Save flow (full-width textarea matching manual description input); when `cover_letter` is non-empty, the section keeps a disabled checked checkbox **and** a read-only expandable `<details class="cover-letter-viewer">` with escaped `<pre class="cover-letter-saved-text">` (shared chrome CSS; unsaved path unchanged: checkbox + paste/Save); applied/interview/stopped cards show `<span class="applied-date">Applied: YYYY-MM-DD</span>` from `applied_at` when set (absolute bottom-right on the card, styled like relevance score); when the applied-date span is rendered, the card `<article>` also gets `has-applied-date` for padding rules; shared corner CSS in `templates/partials/dashboard_card_corners.css` (included by `dashboard.html` and `company_dashboard.html`): feedback padding `7.5rem` right / `1.5rem` bottom when apply date present (via `:has(.applied-date)` and `.has-applied-date` fallback); stopped cards add `1.25rem` bottom margin on `.company-feedback-input`; applied date text appears only after a report rebuild (not updated live on apply); card UI updates come from background report rebuild, not client-side collapse on save; non-empty `company_feedback` sets `data-company-feedback` on the card article
- `dashboard_sorting.py` — unviewed/score and applied list ordering; triage uses `_sort_positions_unviewed_then_score` then `slice_triage_by_non_hidden_limit(items, L)` (only non-hidden count toward L; soft-hidden in walk included; stop after L non-hidden); sort key contract: **unviewed first**, then `relevance_score DESC, updated_at DESC, id ASC` (parity with SQL triage; empty/invalid `updated_at` last); triage records must include `updated_at` (from SQL / `build_dashboard_record` / inbox / enrichment builders) or re-sort+re-slice can drop soft-in-walk extras when scores tie; Edited today preserves DB `updated_at DESC` (no unviewed/score re-sort); applied sort (Applied / Interview / Stopped on main and company): `applied_at` DESC then `updated_at` DESC then `id` ASC; null/empty/invalid dates sort last (missing `applied_at` is rare — legacy/unbackfilled rows; normal apply sets it) — Python layer after DB `(applied_at IS NULL), applied_at DESC, updated_at DESC`
- `dashboard_manager.py` — facade for company and main dashboard renderers; splits applied-stage items into three tabs: Applied (plain applied), Interview (`on_interview=1`), Stopped (`interview_stopped=1`); main dashboard accepts `viewed_today_items` (default card_panel / triage-like cards) and does not re-sort them; company renderer `_render_company_dashboard_html(..., company_id=None, aliases=None)` takes optional `viewed_today_order` (id→order from server `get_viewed_today_jobs`), optional catalog `company_id` (from `resolve_company`; absent/uncatalogued → hide Rename/Delete), and optional `aliases` (raw strings from `get_company_alias_raws`; filtered via `_filter_company_page_aliases` to drop blanks and `company_alias_key` matches of the display name); partitions matching non-applied company items (including soft-hidden) into Edited today in that order, and excludes those ids from Relevant / Not relevant (older viewed jobs can remain on company triage); soft-hidden non-applied rows partition into category by `category` (always visible on company; no Hidden tab / no `.hidden-wrap`); Applied/Interview/Stopped use stage predicates including soft-hidden (`hidden=1`) applied rows; no Show-hidden UI on company; company chrome is a stacked `.company-page-heading` (`H1` = `{safe_company_label} Positions`, muted `.company-total` = `Total in DB: N`, optional compact `<details class="company-aliases">` with `<summary><h2>Aliases (N)</h2></summary>` and a CSS ▸/▼ expand marker when filtered list non-empty — omitted when N=0 / uncatalogued) plus a tab-row `.controls-actions` (shared rule in `dashboard_chrome.css`) with **Rename · Delete · Back** (Back always; Rename/Delete only when `company_id` set; `.rename-company-btn` / `.company-delete-btn` / `.company-back-btn` CSS inline in company template — not `dashboard_companies.css`) calling `renameCompanyOnPage` / `deleteCompanyOnPage` / `backToFullReport` from `partials/dashboard_company_page_actions.js` (prompt/confirm + APIs mirror Companies tab; rename → `/company.html?company=<newDisplayName>`; delete → `/report.html` with no `?tab=companies`; Back → `apiUrl('/report.html')`; no `waitForRebuildThenReload`); `<title>` stays `Company Positions: {name}`; passes `company_label_js` (`json.dumps` + `html.escape(quote=True)`) for onclick safety; main dashboard has `#show-hidden-wrap` / sessionStorage `spejder-show-hidden` (default off) for client-only soft-hide filtering on Relevant / Not relevant / Applied / Interview / Stopped; main `len_relevant_items` / `len_not_relevant_items` = `len(items)` among walk-sliced triage cards; SSR Relevant badge uses split `n + k/N` when embedded soft-hidden `k>0` (assumes Show hidden off / active tab); Not relevant SSR stays `(n+k)/N` until client `refreshCounts` (FOUC on first NR activation accepted); sessionStorage Show-hidden-on restore can briefly keep the split until `DOMContentLoaded` → `refreshCounts` (accepted residual FOUC, same class as NR); client `refreshCounts` / `formatJobListBadge` keep the same active×showHidden×k rules; badge matrix is static-string tested only (no Node/jsdom — residual runtime JS risk accepted); badge totals use `exclude_hidden=False` so soft-hidden count in **N**; renderer also clamps `*_total_count = max(passed, len(items))` and client `refreshCounts` raises `data-total` to at least `n+k` so denominators never sit below cards on the tab; Applied/Interview/Stopped SSR + client badges are a single loaded total `(n+k)` (no slash / split); main tab order: … Not relevant → Applied → Interview → Stopped → Skills → Companies → Edited today (company has no Skills/Companies: … Stopped → Edited today); Edited today shows all matching rows including soft-hidden (no triage cap); main dashboard embeds `<meta name="spejder-report-mtime" content="…">` with an HTTP-date (`formatdate(..., usegmt=True)`) matching `report.html` on-disk mtime after write (placeholder patched post-write (raises if placeholder remains), then `os.utime` restores mtime so `GET /api/report/status` `last_modified` equals the meta tag); when `companies_items` is omitted and `db_path` is set, renderer loads `list_company_catalog_rows`; Companies tab HTML lives in `dashboard_companies_table.py` (`_render_companies_table_html`: select, Action (pen → `renameCompanyRow`, trash → `deleteCompanyRow`), Company link → `openCompanyPage`, Added (`companies.created_at` as `YYYY-MM-DD`), Jobs, Not viewed (`viewed=0` membership), Relevant, Not relevant, Applied, Interview, Stopped, Aliases; stage counts + `data-sort-*`; client sort via `partials/dashboard_companies_sort.js`, default Added DESC); Skills tab HTML lives in `dashboard_skills_table.py` (`_render_skills_table_html`): column order is selection checkbox (header select-all + per-row checkboxes) for bulk Block/Delete, then Action, Skill, Added, Source, Job share, Learned, I have, Want to learn, Not for me; selected rows get `.skill-row-selected` (light green + bolder) and Added-local-today rows get `.skill-row-added-today` (amber), same combined first-cell edge as Companies, via `syncSkillRowHighlights` from `updateSkillsBulkBar` and after Skills sort; per-row Block/Delete are icon buttons with `title`/`aria-label`; Skills action row in `dashboard.html` always shows **Sync from CV** (right-aligned via `.skills-bulk-bar-end`); Block/Delete selected render only when `len_skills_items > 0`; bad-cloud status (`skills_cloud_status_html`) is last in `#panel-skills` (action meanings live in button/column tooltips; no separate legend line), sortable columns (default **Added** newest first, `aria-sort` on active header, keyboard Enter/Space on headers), **Added** column between Skill and Source (`YYYY-MM-DD` from `skill_patterns.created_at`; profile-only skills show `—` with tooltip and `data-sort-added-at="0000"` via `SKILLS_EMPTY_ADDED_AT_SORT` so client ASC/DESC both sort profile-only last), header/cell tooltips, **Job share** (% of jobs with extracted skills), **Learned** (`skill_patterns.occurrences`), **I have** / **Want to learn** / **Not for me** checkbox columns (`data-sort-has-skill`, `data-sort-want-learn`, `data-sort-not-for-me`; client `setUnwantedSkill` plus sibling uncheck — Not for me exclusive with both I have and Want to learn); checkbox toggles refresh row sort data client-side; passes `skills_empty_added_at_sort` into the Jinja context so `partials/dashboard_skills_sort.js` embeds the same sentinel (`SKILLS_EMPTY_ADDED_AT_SORT`) for client-side `compareRows` (`skills_empty_added_at_sort` is embedded in `partials/dashboard_skills_sort.js`, not `dashboard_skills.js`) (Python tests assert the wiring; client `compareRows` behavior is intentionally not covered — no JS test runner in the repo; test boundary); main dashboard toolbar: Portrait icon, Regenerate group, **Profile** gear icon (`#btn-profile`, immediately left of Sync), Sync inbox, Quit (`#btn-quit`, **Enough for today**, rightmost after Sync; company has no Quit); `.regenerate-status` and `.sync-inbox-status` truncate long messages with ellipsis (`max-width: 14rem`); **Portrait** panel (toolbar icon `#btn-portrait`, not a mode tab): embeds committed text from `default_portrait_path` via `embed_portrait_for_textarea` (textarea-safe, not HTML-escaped); passes `has_portrait` for empty-state hint; live edits via `/api/portrait*` when the server is running; **Profile** panel (`#panel-profile`, main only): loads/saves via `/api/profile` and `/api/profile/save` (partials under `templates/partials/profile_panel.*`)
- `dashboard_skills_table.py` — Skills tab table HTML for the main dashboard only (company dashboard has no Skills tab); columns left→right: select, Action (Block/Delete icons), Skill, Added, Source, Job share, Learned, I have, Want to learn, Not for me; also `_render_skills_cloud_status_html` (ngram count / weights / cap / threshold / blocked list with Forgive buttons). Action / Not for me column titles and row button tooltips spell out: **Not for me** = score penalty; **Block** = hide + teach; **Delete** = remove without teaching. Selected / added-today highlights mirror Companies (`.skill-row-selected` / `.skill-row-added-today` via `syncSkillRowHighlights`).
- `dashboard_companies_table.py` — Companies tab table HTML for the main dashboard only (company dashboard has no Companies tab / empty companies context / no companies CSS or JS partials). Columns left→right: select (not sortable), Action (non-sortable: pen via `.rename-company-btn` → `renameCompanyRow`, then trash via `.delete-company-btn` → `deleteCompanyRow`), Company (text), Added (`YYYY-MM-DD` from `created_at`; empty → `—` / `data-sort-added-at="0000"`; tooltip “Catalog row created: …”), Jobs (total), Not viewed (`viewed=0` membership count), Relevant, Not relevant, Applied, Interview, Stopped, Aliases. Bulk bar: Merge ≥2 opens Companies-tab-only `#company-merge-modal` (`partials/dashboard_companies_merge_modal.html` + `dashboard_companies_merge.js`; no `prompt`/`confirm`); candidates built once from `getSelectedCompanyRows()` then stable-sorted by `data-job-count` DESC (ties keep selection/DOM order); list shows names only (`textContent` / `createElement`, no job counts); default display name = first candidate; click a list name fills the input (list is `user-select: text` for copy); Cancel / Escape / backdrop dismiss without merging (ignored while merge request is in flight; Cancel disabled; `#btn-merge-companies` stays disabled while modal open (`updateCompaniesBulkBar` checks `#company-merge-modal` hidden; `openCompanyMergeModal` removeEventListener before Escape handler)); empty trimmed name → `alert` like rename; `companyMergeState.inFlight` latches confirm/open; Merge+Cancel disabled while in flight → `POST /api/company/merge` `{ company_ids, display_name }` → force-close → `waitForRebuildThenReload('companies')` (failure clears latch, re-enables dialog buttons, keeps bulk Merge disabled while modal stays open); Delete ≥1 (`deleteSelectedCompanies` → `POST /api/company/delete-batch`); Rename is per-row only (not bulk; still `prompt`). Selected rows get `.company-row-selected` (slightly bolder text + light green background); rows whose Added date is local today get `.company-row-added-today` (warm amber tint); both classes combine with a green fill and a single amber left edge on the first cell (not per-td inset). Highlights sync via `syncCompanyRowHighlights` from `updateCompaniesBulkBar` and after Companies sort. Stage counts from `list_company_catalog_rows` (same single-scan alias-key membership as `resolve_company` / company page; soft-hidden included; never filter `hidden=0`; **no** Edited-today carve-out from Relevant/Not relevant; `not_viewed_count` is plain `viewed=0` over all membership jobs including soft-hidden). Exclusive stage priority in the scan: Stopped (`applied=1` ∧ `interview_stopped=1`) → Interview (`applied=1` ∧ `on_interview=1`) → Applied (`applied=1` ∧ neither interview flag) → category (`applied≠1` ∧ category Relevant / Not relevant). SSR embeds `data-sort-name`, `data-sort-added-at`, `data-sort-job-count`, `data-sort-not-viewed`, `data-sort-relevant`, `data-sort-not-relevant`, `data-sort-applied`, `data-sort-interview`, `data-sort-stopped`, `data-sort-alias-count` plus `data-job-count` for delete confirm. Client sort mirrors Skills (`companies-sortable` / `companies-sort-active` / `companies-sort-desc` / `companies-sort-indicator`, `aria-sort`); default **Added DESC** (`added_at`, `dir=-1`; rows from `list_company_catalog_rows` already Added DESC for SSR tbody; Added header marked active in SSR; `applySort()` on init); first click Company → ASC, all other keys (including `added_at`, `not_viewed`) → DESC. Wired from `dashboard.html` via `initCompaniesTableSort()` near skills init.
